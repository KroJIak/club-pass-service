# Принципы создания проекта с REST API и мессенджер-ботом

## Архитектурные принципы

### Основные принципы

1. **Многокомпонентная архитектура**: Независимые сервисы (REST API и бот), взаимодействие через HTTP
2. **Разделение ответственности**: Слои - API, бизнес-логика, доступ к данным, обработка событий
3. **Repository Pattern**: Доступ к данным инкапсулирован в репозиториях
4. **Service Layer Pattern**: Бизнес-логика изолирована в сервисах
5. **Многослойная архитектура бота**: Core → Services → Handlers → UI
6. **Контейнеризация**: Все компоненты в Docker, оркестрация через Docker Compose
7. **Версионирование API**: API организовано по версиям через префиксы (например, `/api/v1/`)
8. **Миграции БД**: Использование инструментов миграций (Alembic)
9. **Переменные окружения**: Вся конфигурация через `.env` файл

## Структура проекта

### Основные компоненты

1. **REST API сервис** (`api/` или `api_service/`) - основной API
   - CRUD операции, поиск, валидация через Pydantic
   - Управление пользователями
   - Бизнес-логика
   - Работа с данными
   - Загрузка файлов
   - JWT аутентификация (опционально)
   - Автодокументация (OpenAPI/Swagger)

2. **Bot Service** (`bot/` или `bot_service/`) - бот для мессенджера
   - Обработка сообщений и команд
   - Навигация по меню
   - Интеграция с API
   - Отображение данных пользователю
   - FSM для управления состояниями (опционально)
   - Локализация (опционально)

3. **Mini App** (`mini-app/`) - веб-приложение внутри мессенджера (опционально)
   - Расширенный UI
   - Интеграция с WebApp API мессенджера
   - Взаимодействие с API

### Структура API сервиса

```
api/
├── main.py              # Точка входа FastAPI
├── core/                # config.py, db.py, auth.py
├── api/                 # Endpoints
│   ├── health.py        # Health check
│   ├── routes.py        # Главный роутер
│   └── v1/              # Версия API
│       ├── entity.py    # CRUD сущностей
│       └── files.py     # Загрузка файлов
├── models/              # ORM модели и Pydantic схемы
├── repositories/        # Доступ к данным
└── services/           # Бизнес-логика
```

### Структура бота

```
bot/
├── main.py              # Точка входа
├── core/                # config, states, keyboards, localization, message_manager
├── handlers/            # Обработчики событий (start, list, detail, creation)
├── services/            # Бизнес-логика (api_service, message_service, entity_service)
├── keyboards/           # Компоненты клавиатур
├── pages/               # Страницы интерфейса (опционально)
└── lang/                # JSON файлы локализации (опционально)
```

### Структура Mini App (опционально)

```
mini-app/
├── src/
│   ├── components/      # React/Vue компоненты
│   ├── pages/           # Страницы приложения
│   ├── layout/          # Layout компоненты
│   ├── shared/          # Общие утилиты и типы
│   ├── App.tsx          # Главный компонент
│   └── main.tsx         # Точка входа
└── package.json
```

## База данных

### Структура

**Технология**: PostgreSQL, **Миграции**: Alembic

**Принципы**:
- ORM модели в отдельном модуле
- Репозитории инкапсулируют запросы
- Преобразование ORM → Pydantic в репозиториях
- Транзакции для критических операций
- Одна основная БД для хранения всех данных (пользователи, сущности, конфигурация)

## Docker Compose

### Принципы

- Мультисервисная архитектура (БД, API, бот, mini-app при необходимости)
- Общий `.env` файл для всех сервисов
- Volumes для медиафайлов и данных БД
- Отдельные Dockerfile для каждого сервиса
- Health checks для зависимостей
- Restart policies для автоматического перезапуска

## Паттерны и практики

### Архитектурные паттерны

1. **Repository Pattern**: Доступ к данным через репозитории для разделения логики доступа к данным
2. **Service Layer Pattern**: Бизнес-логика изолирована в сервисах
3. **Dependency Injection**: Зависимости через параметры
4. **Facade**: Упрощение сложных подсистем (MessageService, StateService)

### Практики

1. **Версионирование API**: API организовано по версиям через префиксы (`/api/v1/`)
2. **Валидация**: Валидация через Pydantic (Python) или Zod (TypeScript)
3. **Async/await**: Async/await для всех I/O операций
4. **Type hints**: Type hints для типизации
5. **FSM**: FSM для управления состояниями бота (опционально)
6. **Локализация**: Локализация через JSON файлы (опционально)
7. **Кэширование**: Кэширование ресурсоемких операций
8. **JWT Аутентификация**: Создание токена при логине, валидация в защищенных endpoints
9. **Обработка ошибок**: Единый формат ошибок во всех API с кодами и сообщениями
10. **Health Checks**: Все сервисы должны иметь health check endpoints для мониторинга

### Миграции БД (Alembic)

Использование Alembic для управления миграциями базы данных:
- Версионирование схемы БД
- Автоматическая генерация миграций из моделей
- Откат миграций при необходимости
- Структура: `alembic/versions/` для файлов миграций
- Команды: `alembic revision --autogenerate`, `alembic upgrade head`, `alembic downgrade`

## Последовательность создания

1. **Инициализация**: Структура директорий, git, requirements.txt, виртуальное окружение
2. **БД**: docker-compose.yml с БД, настройка Alembic, первая миграция
3. **REST API**: Структура, FastAPI app, config, БД подключение, модели, Pydantic схемы, репозитории, endpoints, роутинг, health-check, статика
4. **Загрузка файлов** (опционально): ORM модель, сервис, API endpoints, файловая система
5. **Bot Service**: Структура, config, локализация (опционально), FSM (опционально), keyboards, message_manager, api_service, сервисы, handlers, main.py
6. **Mini App** (опционально): Компоненты, страницы, интеграция с API
7. **Контейнеризация**: Dockerfile для API и бота, docker-compose.yml, .env, volumes
8. **Тестирование**: API тесты, тесты бота, документация, README

## Ключевые принципы

### Организация кода

- Разделение по слоям
- Единственная ответственность
- DRY (Don't Repeat Yourself)
- Зависимость от абстракций
- Независимость сервисов - каждый сервис развертывается отдельно

### Работа с данными

- ORM вместо прямого SQL
- Транзакции для критических операций
- Валидация через Pydantic/Zod
- Явное преобразование между слоями (ORM → Pydantic)

### Разработка бота

- Минимальная логика в handlers
- FSM для состояний (если нужно)
- Понятные сообщения
- Локализация (если нужно)
- Graceful обработка ошибок

### Конфигурация

- Все через переменные окружения
- Единый `.env` файл
- Безопасные значения по умолчанию
- Валидация через Pydantic Settings

### Безопасность

- Валидация входных данных
- Централизованная обработка исключений
- Безопасное хранение файлов
- JWT аутентификация (если нужно)
- Хеширование паролей
- Шифрование данных

### Документация и мониторинг

- OpenAPI/Swagger для всех API
- Структурированное логирование
- Graceful shutdown - корректное завершение работы
- Rate limiting - ограничение частоты запросов

## Дополнительные рекомендации

- **Тестирование**: unit и integration тесты
- **CI/CD**: автоматическая сборка и деплой
- **Мониторинг**: логирование и метрики (Prometheus, Grafana)
- **Кэширование**: Redis для кэширования данных
- **Очереди**: RabbitMQ/Kafka для асинхронной обработки
- **Валидация**: схемы валидации данных (Pydantic, Zod)
- **Webhooks**: использовать webhooks вместо long polling (если поддерживается)
- **Масштабирование**: горизонтальное масштабирование через Docker Swarm/Kubernetes
